# withDataQuery

`withDataQuery<T>()` is a headless NgRx SignalStore feature
(`@m3kit/state`) that owns the full report-query lifecycle for any
`TableDataSource<T>` from `@m3kit/core`: free-text filter (debounced),
per-field exact-match filters, sort, pagination, stale marking, normalized
`ReportError`s, telemetry, and the fetched page (`rows`, `totalCount`,
`loading`, `error`).

It follows the connect-free datasource contract: every query mutation
re-invokes `fetch` through a single `switchMap`ped `rxMethod`, so stale
in-flight responses are cancelled and the newest query always wins.

**Layer:** state feature — no template, no styles; pairs naturally with
[DataTable](?path=/docs/organisms-datatable--docs) and
[TableFilterBar](?path=/docs/molecules-tablefilterbar--docs).

## Usage

The store's state signals map one-to-one onto `m3k-data-table`'s
controlled-mode inputs, and the table's `sortChange`/`pageChange` outputs
map straight back onto the store's methods — the store is the single
fetch path, the table never touches the data source
(see the live wiring in
[DataTable/StoreDriven](?path=/story/organisms-datatable-storedriven--store-driven)):

```ts
import { Component, inject } from '@angular/core';
import { signalStore } from '@ngrx/signals';
import { InMemoryTableDataSource, TableDefinition } from '@m3kit/core';
import { withDataQuery } from '@m3kit/state';
import { DataTableComponent } from '@m3kit/table';

interface Invoice {
  id: number;
  customer: string;
  status: string;
  amount: number;
}

const InvoiceStore = signalStore(withDataQuery<Invoice>());

@Component({
  selector: 'app-invoices',
  imports: [DataTableComponent],
  providers: [InvoiceStore],
  template: `
    <input (input)="store.setTextFilter($any($event.target).value)" />
    <m3k-data-table
      [definition]="definition"
      [rows]="store.rows()"
      [loading]="store.loading()"
      [error]="store.errorMessage()"
      [totalCount]="store.totalCount()"
      [sort]="store.sort()"
      [page]="store.page()"
      (sortChange)="store.setSort($event)"
      (pageChange)="store.setPage($event)"
    />
  `,
})
export class InvoicesComponent {
  readonly definition: TableDefinition<Invoice> = INVOICE_DEFINITION;
  readonly store = inject(InvoiceStore);

  constructor() {
    this.store.connect(
      new InMemoryTableDataSource<Invoice>(rows, {
        textSearchKeys: ['customer'],
      })
    );
  }
}
```

Binding `[rows]` switches the table to controlled mode: it stops
fetching from any `dataSource` of its own and renders exactly the state
the store fetched, so there is one fetch pipeline, not two.

## API

### Options — `withDataQuery<T>(options?)`

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `debounceMs` | `number` | `300` | Debounce window for `setTextFilter`. |
| `initialPageSize` | `number` | `25` | Page size of the initial query. |
| `reportId` | `string \| undefined` | `undefined` | Stable report id for telemetry. Omit to disable emissions. |

### State signals

| Signal | Type | Description |
| --- | --- | --- |
| `query` | `Signal<DataQuery>` | The complete query (filter + sort + page). |
| `rows` | `Signal<readonly T[]>` | Rows of the most recently fetched page. |
| `totalCount` | `Signal<number>` | Filtered (pre-pagination) row count. |
| `loading` | `Signal<boolean>` | A fetch is in flight. |
| `error` | `Signal<ReportError \| null>` | Normalized last fetch error, or `null`. |
| `hasFetched` | `Signal<boolean>` | True after at least one fetch completes (success, empty, or error). |
| `stale` | `Signal<boolean>` | True when the latest settled successful/empty result was marked stale. |

### Computed signals

| Signal | Type | Description |
| --- | --- | --- |
| `textFilter` | `Signal<string>` | Current free-text filter (`''` when unset). |
| `fieldFilters` | `Signal<Record<string, unknown>>` | Current exact-match field filters. |
| `sort` | `Signal<SortState \| null>` | Current sort. |
| `page` | `Signal<PageState>` | Current pagination. |
| `pageCount` | `Signal<number>` | Pages implied by `totalCount` / page size. |
| `isEmpty` | `Signal<boolean>` | Completed fetch matched no rows. |
| `errorMessage` | `Signal<string \| null>` | Convenience message for UI bindings like table `[error]`. |
| `loadState` | `Signal<LoadState<DataPage<T>>>` | Six-kind reporting taxonomy: `idle`, `loading`, `refreshing`, `success`, `empty`, `error`. |

### Methods

| Method | Description |
| --- | --- |
| `connect(dataSource)` | Connects a `TableDataSource<T>` and runs the current query. Reconnecting replaces the source and refetches. |
| `refresh()` | Re-runs the current query. |
| `markStale()` | Marks the current settled successful/empty result stale; the flag clears on the next successful fetch. |
| `setTextFilter(text)` | Debounced + deduplicated free-text filter; whitespace clears it. Resets to page 0. Also accepts a `Signal<string>` or `Observable<string>` (it is an `rxMethod`). |
| `setFieldFilters(fields)` | Replaces the exact-match field filters. Resets to page 0. |
| `setSort(sort)` | Sets or clears (`null`) the sort. Resets to page 0. |
| `setPage(page)` | Sets `{ index, size }` (zero-based index). |

## Do / Don't

- **Do** bind a search input straight to `setTextFilter` — debouncing and
  dedup live in the store, not the template.
- **Don't** bind `[dataSource]` on `m3k-data-table` when the store drives
  it — the store owns the single fetch path; the table renders
  `rows`/`loading`/`errorMessage`/`totalCount`/`sort`/`page` and reports intent
  via `sortChange`/`pageChange`.
- **Do** provide `REPORT_TELEMETRY_REPORTER` at the app boundary when you
  want telemetry. With `reportId` set, the feature emits redacted
  `query_changed`, `fetch_started`, `fetch_succeeded`, `fetch_failed`, and
  `empty_result` events with `queryHash` identity (never raw filter text);
  the default token factory is a no-op.
- **Do** rely on the `switchMap` semantics: rapid query changes never
  produce out-of-order results.
- **Don't** import `@ngrx/operators` for `tapResponse` — the kit's
  dependency surface is `@ngrx/signals` only (THE CONTRACT, rule 4); the
  feature ships a local clean-room equivalent.
