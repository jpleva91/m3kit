# m3kit

A rethemable Material 3 UI component kit — a reference implementation of a
reporting UI toolkit built with Angular,
Angular Material (M3), and NgRx Signals. Everything here is standalone,
signals-first, `OnPush`, and strictly typed. All demo data is synthetic
(customers, orders, invoices, products, support tickets).

## Library map

| Library | Import path | Contents |
| --- | --- | --- |
| **core** | `@m3kit/core` | Framework-agnostic contracts: `ReportDefinition`, `ReportColumnDef`, `ReportQuery`, `ReportPage`, `ReportDataSource`, `InMemoryReportDataSource`, query/page helpers. No Material dependency. |
| **material** | `@m3kit/material` | Material-based report UI: `ReportTable`, `ReportToolbar`, `ReportFilterBar`. |
| **dashboard** | `@m3kit/dashboard` | Dashboard building blocks: `KpiCard`, `DetailCard`, `DashboardGrid`. |
| **forms** | `@m3kit/forms` | Typed reactive-form helpers: `FormField`, `FormSection`, `FilterForm`. |
| **testing** | `@m3kit/testing` | Synthetic data factories (`makeInvoices`, `makeCustomers`, …) and ready-made report definitions for specs and demos. |

The stories in this Storybook are grouped to match: **Material/**,
**Dashboard/**, **Forms/**, and **App/** (components from the demo
application that compose the libraries).

## Boundary rules

Dependencies are enforced by lint (`@nx/enforce-module-boundaries`):

- `dashboard`, `forms`, `material`, and `testing` may depend on **core only**.
- The demo **app** may depend on all libraries.
- Library stories never import `@m3kit/testing` — they use small local
  fixtures so each library stays self-contained.

## M3 theming

Components consume Material 3 system tokens (`var(--mat-sys-*)`) — no
hardcoded colors. The theme is defined once with `mat.theme` and exposes
light and dark color schemes. Use the **Theme** toolbar control above to
flip the preview between light and dark; every story should render
correctly in both without story-level background overrides.

## Adoption

This repository uses a copy-in model: copy the libraries you need into your
workspace (keeping the `core` → consumer direction), wire up the TypeScript
path aliases, and adapt the demo app patterns to your own data sources by
implementing `ReportDataSource`.
