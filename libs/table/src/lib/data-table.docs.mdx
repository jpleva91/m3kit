# DataTable

`m3k-data-table` renders a Material table from a declarative
`TableDefinition<T>`, in one of two modes:

- **Uncontrolled (default):** bind `dataSource` and the table owns the
  full query state (text filter, field filters, sort, page) as signals,
  re-fetching from the `TableDataSource<T>` on every change.
- **Controlled:** bind `rows` (its presence switches the mode) and the
  table never fetches — it renders externally owned state
  (`rows`/`loading`/`error`/`totalCount`/`sort`/`page`) and emits
  `sortChange`/`pageChange` so the owner (typically a `withDataQuery`
  SignalStore from `@m3kit/state`) stays the single fetch path. See the
  [StoreDriven story](?path=/story/organisms-datatable-storedriven--store-driven).

Use it for any tabular report where columns, formatting, sorting, and
pagination should be driven by data rather than hand-written templates.
It ships type-aware cell formatting (`text`, `number`, `date`,
`currency`, `badge`), a loading bar, an empty state, a distinct
error state, and optional headless column view-state for hiding,
reordering, pinning, and width overrides.

**Atomic level:** Organism — composed from Material table, sort header,
paginator, and progress bar atoms, plus the `@m3kit/core` query contracts.

## Usage

```ts
import { Component } from '@angular/core';
import { InMemoryTableDataSource, TableDefinition, type ColumnViewState } from '@m3kit/core';
import { DataTableComponent } from '@m3kit/table';

interface InvoiceRow {
  readonly id: string;
  readonly customerName: string;
  readonly amount: number;
  readonly status: 'draft' | 'sent' | 'paid' | 'overdue';
  readonly issuedAt: Date;
}

@Component({
  selector: 'app-invoices',
  imports: [DataTableComponent],
  template: `
    <m3k-data-table
      [definition]="definition"
      [dataSource]="dataSource"
      [textFilter]="''"
      [columnState]="columnState"
      (rowClicked)="open($event)"
    />
  `,
})
export class InvoicesComponent {
  readonly definition: TableDefinition<InvoiceRow> = {
    id: 'invoices',
    title: 'Invoices',
    columns: [
      { key: 'id', header: 'Invoice #', type: 'text', sortable: true },
      { key: 'customerName', header: 'Customer', type: 'text', sortable: true, filterable: true },
      {
        key: 'amount',
        header: 'Amount',
        type: 'currency',
        sortable: true,
        align: 'end',
        format: { currencyCode: 'USD', digitsInfo: '1.2-2' },
      },
      {
        key: 'status',
        header: 'Status',
        type: 'badge',
        filterable: true,
        format: { badgeColors: { draft: 'default', sent: 'info', paid: 'success', overdue: 'warn' } },
      },
      { key: 'issuedAt', header: 'Issued', type: 'date', sortable: true },
    ],
    defaultSort: { key: 'issuedAt', direction: 'desc' },
    defaultPageSize: 10,
  };

  readonly dataSource = new InMemoryTableDataSource<InvoiceRow>(rows);

  readonly columnState: readonly ColumnViewState[] = [
    { key: 'id', pinned: 'start', width: '9rem' },
    { key: 'amount', pinned: 'end', width: '10rem' },
    { key: 'customerName', width: '20rem' },
    { key: 'status' },
    { key: 'issuedAt', visible: false },
  ];

  open(row: InvoiceRow): void {
    // navigate to detail
  }
}
```

## Column view-state

Bind `[columnState]` to apply a headless `ColumnViewState[]` on top of the
static definition. The state array is display order: unknown keys are ignored,
duplicate keys are first-wins, unlisted definition columns are appended, and
`visible: false` hides a column. `pinned: 'start' | 'end'` renders sticky
columns at the corresponding horizontal edge, and a state `width` overrides the
column definition's `width`. The table does not provide column-picker, drag, or
resize UI; apps and saved views own writing the state.

## Controlled mode — store-driven

Binding `[rows]` switches the table to controlled mode: `dataSource` is
ignored (never fetched), the provided state renders as-is, and sort/page
interactions surface as events instead of feeding the internal pipeline.
A `withDataQuery` store composes onto the bindings one-to-one:

```html
<m3k-data-table
  [definition]="definition"
  [rows]="store.rows()"
  [loading]="store.loading()"
  [error]="store.error()"
  [totalCount]="store.totalCount()"
  [sort]="store.sort()"
  [page]="store.page()"
  (sortChange)="store.setSort($event)"
  (pageChange)="store.setPage($event)"
/>
```

## Inputs and outputs

| Name | Kind | Type | Default | Description |
| --- | --- | --- | --- | --- |
| `definition` | input (required) | `TableDefinition<T>` | — | Declarative report definition driving columns, formatting, default sort, and default page size. |
| `dataSource` | input | `TableDataSource<T> \| undefined` | `undefined` | Source the table fetches pages from on every query change (uncontrolled mode). Ignored while `rows` is bound. |
| `textFilter` | input | `string` | `''` | Free-text filter applied across searchable fields (uncontrolled mode; wire to `m3k-table-filter-bar`'s `filterChange`). |
| `fieldFilters` | input | `Readonly<Record<string, unknown>>` | `{}` | Per-field exact-match filters, keyed by row property (uncontrolled mode; wire to `m3k-filter-form`'s `filtersChange`). |
| `columnState` | input | `readonly ColumnViewState[] \| undefined` | `undefined` | Optional headless view-state for column visibility, order, pinning, and width overrides. |
| `rows` | input | `readonly T[] \| undefined` | `undefined` | Externally fetched rows. Binding a value switches the table to controlled mode. |
| `loading` | input | `boolean \| undefined` | `undefined` | External loading flag (controlled mode). |
| `error` | input | `string \| null \| undefined` | `undefined` | External error message, rendered in the error row; `null` when healthy (controlled mode). |
| `totalCount` | input | `number \| undefined` | `undefined` | External filtered (pre-pagination) row count for the paginator (controlled mode; falls back to `rows.length`). |
| `sort` | input | `SortState \| null \| undefined` | `undefined` | External sort state shown by the headers (controlled mode). |
| `page` | input | `PageState \| undefined` | `undefined` | External pagination state shown by the paginator (controlled mode). |
| `rowClicked` | output | `T` | — | Emits the clicked (or Enter/Space-activated) row. |
| `sortChange` | output | `SortState \| null` | — | Emits the sort the user chose via a header (`null` clears). Fired in both modes; in controlled mode it is the only effect. |
| `pageChange` | output | `PageState` | — | Emits the page index/size the user chose via the paginator. Fired in both modes; in controlled mode it is the only effect. |

Public API beyond inputs: `applyTextFilter(text)` and
`applyFieldFilters(fields)` set filters imperatively in uncontrolled mode
(overriding the inputs); `isLoading`, `hasError`, `controlled`, and
`query` are readable signals.

## Theming

Token-only styling. The component consumes:

- `--mat-sys-surface-container` — row hover background
- `--mat-sys-surface` — sticky column cell background
- `--mat-sys-outline-variant` — pinned-edge divider
- `--mat-sys-primary` — row focus-visible outline
- `--mat-sys-on-surface-variant` — empty-state cell text
- `--mat-sys-error` — error-state cell text
- `--app-font-data` — monospace numerals (tabular figures) in `number`, `currency`, and `date` cells
- `--app-radius-badge` — badge corner radius
- `--app-status-{draft,sent,paid,overdue,void}-{bg,fg}` — badge colors, mapped from `badgeColors` values (`default`/`neutral` → draft, `primary`/`info` → sent, `success` → paid, `warn` → overdue, `accent` → void)

Density is locked to `-2` (compact, analytical) via a host-scoped
`mat.theme` re-emission, per DESIGN.md.

## Do / Don't

- **Do** drive filtering through `textFilter` / `fieldFilters` (or the
  imperative `apply*` methods) and let the table own sort and page state
  in uncontrolled mode — it resets to page 1 on any filter or definition
  change for you.
- **Do** pick exactly one mode per table: either the table fetches
  (`dataSource`) or a store does (`rows` + friends) — never both
  pipelines at once.
- **Don't** pre-filter or pre-sort the rows you hand to the data source to
  mirror UI state; the table sends the complete `DataQuery` to
  `TableDataSource.fetch` and duplicating that logic outside desynchronizes
  the paginator's total count.
