# Implementation Plan: Reporting Reference Workspace Scaffold

**Branch**: `001-reporting-scaffold` | **Date**: 2026-06-11 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `/specs/001-reporting-scaffold/spec.md`

## Summary

Scaffold a public, clean-room Angular/Nx reporting reference workspace: an Nx 20
Angular monorepo with one standalone demo application and three reporting libraries,
lint-enforced module boundaries, a Material shell with a lazily loaded placeholder
`/reports` route, the governance/adoption documentation set, and Apache-2.0
licensing. Scaffold-only: placeholder exports, no reporting features. Exit criterion
is a fully green `nx run-many -t lint test build` across all four projects,
reproducible from a fresh clone.

**Structure Decision**: Nx 20 Angular monorepo with `apps/` + `libs/` per the
canonical Nx Angular-monorepo layout. The demo app is disposable during
internalization; everything reusable lives in the three `libs/reporting/*`
libraries. Import paths are mapped in `tsconfig.base.json` as `@reporting/core`,
`@reporting/material`, and `@reporting/testing` — the single documented rename
point for adopters. Libraries are standard non-publishable Nx Angular libraries
(no buildable/publishable machinery), generated with Jest unit testing and no
e2e (unit testing since migrated to Vitest; see DECISIONS.md ADR-005 amendment,
2026-06-11).

### Module Boundaries

Tags (in each `project.json`):

| Project | Tags |
|---|---|
| `apps/demo-reporting` | `type:app`, `scope:demo` |
| `libs/reporting/core` | `type:lib`, `scope:reporting-core` |
| `libs/reporting/material` | `type:lib`, `scope:reporting-material` |
| `libs/reporting/testing` | `type:lib`, `scope:reporting-testing` |

Dependency rules: `core` depends on nothing internal; `material → core`;
`testing → core`; the app may depend on all three libs. All other internal
directions (`core → material`, `material → testing`, `testing → material`) are
lint errors.

`@nx/enforce-module-boundaries` block in the root flat ESLint config:

```js
'@nx/enforce-module-boundaries': [
  'error',
  {
    enforceBuildableLibDependency: true,
    allow: ['^.*/eslint(\\.base)?\\.config\\.[cm]?js$'],
    depConstraints: [
      {
        sourceTag: 'scope:reporting-core',
        onlyDependOnLibsWithTags: [], // core depends on no internal projects
      },
      {
        sourceTag: 'scope:reporting-material',
        onlyDependOnLibsWithTags: ['scope:reporting-core'],
      },
      {
        sourceTag: 'scope:reporting-testing',
        onlyDependOnLibsWithTags: ['scope:reporting-core'],
      },
      {
        sourceTag: 'type:app',
        onlyDependOnLibsWithTags: [
          'scope:reporting-core',
          'scope:reporting-material',
          'scope:reporting-testing',
        ],
      },
    ],
  },
],
```

The permissive catch-all (`sourceTag: '*'` → `['*']`) is intentionally omitted so
that violations fail lint. Verification: temporarily add a forbidden import (the
material library from inside the core library), confirm lint fails on the core
project, revert, and record the check in `docs/BOUNDARY_LOG.md`.

### Tooling Decisions

- **Builder**: esbuild application builder (Nx 20 / Angular 19 default). No webpack,
  no custom builders — favors copy-in-ability.
- **Lint**: ESLint flat config exactly as generated by Nx 20; the only addition is
  the boundary `depConstraints` above.
- **Unit tests**: Jest via Nx defaults at scaffold time (since migrated to
  Vitest; see DECISIONS.md ADR-005 amendment, 2026-06-11); one trivial passing
  spec per project so
  `nx run-many -t test` is meaningful.
- **Format**: Prettier with Nx-default config; no opinionated overrides.
- **E2E**: none in the scaffold phase; deliberately deferred.
- **No publishing setup**: libs are non-publishable; the adoption model is source
  import, not npm.
- **CI-readiness**: no CI provider config is committed in this phase, but
  `npx nx run-many -t lint test build` passing for all four projects is the contract
  any future CI wraps, and the scaffold exit criterion.

### Risks & Mitigations

| Risk | Mitigation |
|---|---|
| Version drift — tooling auto-resolves Angular 20+ / Nx 21 / Material latest, breaking the pinned stack. | Pin the workspace generator to Nx 20; install `@angular/material@~19.2.0 @angular/cdk@~19.2.0` explicitly before running any ng-add schematic; tilde ranges for `@angular/*`; commit the lockfile; verify `package.json` versions immediately after generation. |
| Phantom abstraction — scaffold phase grows real features "while we're here". | Hard scope: placeholder exports only, toolbar+sidenav shell only, no table/filter/datasource implementations. Feature work is listed under Out of Scope in the spec and blocked behind the review gate. |
| Clean-room leakage — non-synthetic names, shapes, or workflows creep into types, fixtures, or docs. | Synthetic domains only; `docs/CLEAN_ROOM.md` and `docs/BOUNDARY_LOG.md` created before any code; the log is appended at the time of each consultation; the review gate audits the full scaffold before feature phases. |
| Copy-in friction — exotic build steps or deep external deps make source-internalization painful. | esbuild defaults, no custom executors, non-publishable libs, minimal dep set, conventional Nx layout; `docs/INTERNALIZATION_GUIDE.md` documents the exact copy-in path. |
| Nx/Angular compatibility mismatch — an Nx 20 minor that predates Angular 19.2 support. | Use Nx 20.8.4 (the terminal Nx 20 release, which generates Angular `~19.2.0`); confirm resolved versions with `nx report`; record them in the README and `docs/DECISIONS.md`. |
